# Tool map (server v0.13.0)

The machine-readable copy is `tests/contract/tools.json` in the plugin repository; the lint keeps the
two consistent with every file of the plugin. Status "now" means exposed by server v0.13.0.

## Available now

| Tool | Parameters | Cost | Use |
|---|---|---|---|
| `seocli:get_status` | none | free | Service name and version; session check. A `unauthorized` error means the account is pending or not logged in. |
| `seocli:manage_clients` | `action`: create, list, get, rename, set_seller_name, archive, restore, delete; `id`, `domain`, `name`, `seller_name`, `status` (list filter) | free | Clients are the sites the account follows. `create` needs `domain` (name defaults to the domain) and takes an optional `seller_name`; `get`, `rename`, `set_seller_name`, `archive`, `restore`, `delete` need `id`. `seller_name` is the store name as Google Shopping shows it (3-100 characters, always in the answer, `null` when missing): `set_seller_name` without it removes it; the client's Shopping checks use it on their own. `delete` is irreversible. |
| `seocli:get_credit_balance` | none | free | `included` (this period), `topup`, `total`, and `plan`: the account plan (`pending` = waiting for activation, `beta`; later `active`, `suspended`). |
| `seocli:list_credit_movements` | `from`, `to` (`YYYY-MM-DD`, UTC, inclusive; default: start of the current credit period to today), `client_id` (uuid or `none`), `limit` (1-500, default 100), `cursor` | free | Credit ledger, newest first: `movements[]` with `kind`, signed `credits` (balance change) and `amount`; `summary[]` per client with `charged` over the whole period; `next_cursor` until the last page. A reservation subtracts the estimate, a release returns the unused part, a confirmation records the charge in `amount` with 0 change. |
| `seocli:get_price_list` | none | free | `version` and `items[]` with `operation` code, `description`, `unit`, `credits`. |
| `seocli:check_serp` | `keywords` (1-10), `country` (ISO, default IT), `language` (default it), `device` (desktop/mobile), `client_id` **or** `domain` (pre-sales, not saved), `refresh` (force new data at full price), `max_credits` | **paid**: 3 credits per page of 10 results read; reading stops at the page where the site appears; estimate 30 per keyword, charge = pages read. Shared 24 h cache: data already paid by this account = free; any other check = full price (pages needed by the site), with `collected_at` showing the data date; `refresh` = full price | Per keyword: `position` (`ranked: false` if not in the first 100), `url`, `other_urls`, up to 10 `competitors` (position, domain, url), `features` (people_also_ask, local_pack, shopping, ai_overview *seen on the page*), `pages_read`, `mode` live, `origin` (`fresh` or `cache`: then `collected_at` is the date of the cached data, up to 24 h old); `failed` keywords make the answer `partial` and are not charged. Titles of third-party results only in `external_sources` (`type` serp_result, `url`, `title`, `collected_at`). A client check goes to the client's history. Repeating a finished check returns the cached data (free if already yours); only a request still running answers `partial` "richiesta identica". |
| `seocli:check_geo` | `keyword`, `country`, `language`, `device`, `client_id` **or** `domain`, `engines` (`ai_overview` default, `chatgpt`, `gemini`, `perplexity`, `claude`), `question` (a natural question in the user's language that you write and show the user first; default: the keyword), `samples` (1-30, default 10), `refresh` (skip the cache), `max_credits` | **paid** per sample and per engine: AI Overview 8, ChatGPT 30, Gemini 50, Perplexity 10, Claude 70 credits (estimate = samples × sum of the chosen engines; 10 samples on all four AI engines = 1,600, above the default ceiling of 500: always show it and pass `max_credits`); only successful samples are charged. Shared 7-day lot cache: samples already paid by this account are free; samples from the cache paid by others and new samples cost 8 each; `refresh` reads all samples fresh | Background: returns an operation id at once; read the result with `seocli:get_operation` (samples take 10-45 s each, run in parallel). Engines run in the same operation; only the question reaches them (never the site or client data). Client checks go to the client's GEO history. |
| `seocli:get_visibility_history` | `client_id`, `keyword` (optional), `kind` (`serp`, `geo`, `shopping`, `all`), `from`/`to` (`YYYY-MM-DD`, default last 90 days) | free | Client history only (pre-sales checks are never stored). `series[]`: SERP per keyword (points with position or none, URL; changes `rise`, `fall`, `entered`, `left`), GEO per engine and question (one point per check with samples, rate and Wilson interval; changes `new_citation`, `lost_citation`, `insufficient_sample`), `shopping_search` per keyword (`site_count`, `best_position`, `match_rule`, `price_min`/`price_avg`/`price_max`, `currency`; changes on the best position) and `shopping_offers` per product (`product_id`, `product_url`, `source`; points with `site_total`, `gap_min`, `gap_min_percent`, `gap_avg`, `gap_avg_percent`, `currency`; no changes). The product title is only in `external_sources` (`type` shopping_product), pointed to by `source`. With `keyword` only the Shopping searches of that keyword, no offers series. Each series has `chart` (`title`, `unit`, `inverted_axis`): draw it (see `SKILL.md`). GEO series also carry `question` when it differs from the keyword. `truncated` when a series exceeds 500 points; `omitted_series` > 0 when the answer hit its size cap: call again with `keyword` for the missing series. |
| `seocli:check_shopping` | `keyword`, `country` (default IT), `language` (default it), `client_id` **or** `domain` (pre-sales, not saved), `seller_name` (optional, 3-100 characters: the store name as Google Shopping shows it), `refresh`, `max_credits` | **paid**: 3 credits per search. Shared 24 h cache: already paid by this account = free; paid by others = full price, with `collected_at`; `refresh` = full price. Synchronous (answer at once, 45 s at most, nothing charged on failure) | Public Google Shopping results, not Merchant Center. About 40 `products[]` (`position`, `price`, `old_price`, `currency`, `rating`, `votes`, `product_id` (absent = no product page: offers cannot be asked), `shopping_url`, `source`, `site_match`), `shops[]` (up to 10 most present stores), `prices` (min, avg, max in the most frequent currency, `included`, `excluded`), `site` (`count`, `best_position`, `positions`; `count` 0 is not an error). The search does not know sellers' domains: a product is the site's if `seller_name` is contained in the store name, or the site's domain (without `www.`) is contained in it; `site_match` says which rule (`seller_name` or `domain`). With `client_id` and no `seller_name` the client's saved store name is used (a `seller_name` in the request wins and does not change it; never with `domain`); the answer's `seller_name` says which name was used (`null` = domain only). When the domain does not match and the client has no saved name, ask the user for the store name as it appears on Google Shopping and save it with `manage_clients` `set_seller_name` (cache: repeating is free if already yours). Titles and store names only in `external_sources` (`type` shopping_product, field `seller`), pointed to by `source` (index). A client check goes to the client's history: read it with `get_visibility_history` `kind` `shopping`. |
| `seocli:check_shopping_offers` | `product` (the `product_id` from `check_shopping` or the https address of the Google Shopping product page; the address is never fetched), `country`, `language`, `client_id` or `domain` (optional), `seller_name`, `refresh`, `max_credits` | **paid**: 3 credits per product; same 24 h cache and synchronous behaviour as `check_shopping` | Seller offers Google shows for one product (a handful, up to about ten): `offers[]` (`position`, `domain`, `url`, `base_price`, `shipping_price`, `total_price`, `currency`, `availability`, `condition`, `source`, `site_match`) and `site` (the site's lowest `total_price` with gap in value and percent from the minimum and the average of the other sellers, `compared` = how many), `seller_name` (the store name used: the request's or the client's saved one, `null` if none). The client's saved store name applies as in `check_shopping`. `site` null = no offer of the site among these, **not** "the site does not sell it": Google may omit a store seen in the search. Without a site, `site` is null; if the site is the only seller the gaps are missing. Titles, seller names and offer details only in `external_sources` (`type` shopping_offer, field `seller`). |
| `seocli:get_operation` | `id` | free | `status` (queued, running, completed, partial, failed), `kind`, `client_id`, `cost`, `outcome`, timestamps. For a finished GEO check also `result`: per engine (`engines[]`, each with `search_activated`: an engine that answered without searching the web is a valid outcome), samples, AI Overview presence, `cited` and `mentioned` as `{count, total, rate, low, high}` (Wilson 95% interval), `ai_overview_absent` (Google showed no AI Overview in any sample: say so, do not suggest more samples), `insufficient_sample` (AI Overview seen but fewer than 10 successful samples and no citation: never say "not cited"), an approximation note, `fresh_samples` / `cache_samples` and `oldest_sample_at` (say how old the cached samples are); cited sources in `external_sources` with how many samples cited them. |
| `seocli:delete_account` | `confirm` (default false) | free | **Destructive request.** Without `confirm` nothing is written: `will_delete` and `will_keep` list the data categories (clients and their history, operations, balance, login identity with the email; the credit ledger is kept 10 years under a pseudonymous id). With `confirm: true` the request is registered **to be confirmed** (`requested`, `request_id`, `requested_at`, `confirmed` false, `confirmation_expires_at`) and an email with a confirmation link (valid 72 h) goes to the login address: the request counts, and the seocli team is notified, only after the user presses the button on the page of that link; then the team deletes within `within_days` (30) and another email confirms the deletion. Repeating within 10 minutes sends nothing ("check your inbox"); later it sends a new link that replaces the old one; an already confirmed request returns `confirmed: true`. `email_required` if the login profile has no email. Allowed also for pending accounts. |

Price-list codes today: `serp_queued`, `serp_live`, `geo`, `shopping_search`, `shopping_sellers`, `keyword_research`, `page_crawl`,
