# JavaScript rendering, mobile-first indexing, Core Web Vitals

Tags as in `crawling-indexing.md`.

## Rendering

- `[G:js-seo]` (updated 2026-03-04) Pages with status 200 go to the render queue; non-200 may skip rendering.
  Links must be `<a href>`; JS may inject them. Use the History API, not `#` routes. Google does not render
  JavaScript of URLs blocked in robots.txt. Canonical via JS only if equal to the raw HTML; avoid several.
  A `noindex` in raw HTML may stop rendering, so removing it with JS may not work; do not ship `noindex`
  if the page should be indexed later. JSON-LD can be generated by JS. Shadow DOM is flattened; verify with
  URL Inspection or the Rich Results Test. Fingerprint file names because Googlebot caches aggressively.
- Strategy table `[H]`:

| Strategy | Verdict | Watch for |
|---|---|---|
| SSG | best for stable content | rebuild time, stale prices |
| ISR or stale-while-revalidate | excellent for large catalogues | stale window, webhook revalidation |
| SSR | good if TTFB is controlled | slow server wrecks LCP |
| Client-only SPA | risky | empty HTML, soft 404, render delay |
| Islands or partial hydration | excellent | JS cost raises INP |
| Dynamic rendering | legacy workaround | do not start new builds on it |

- `[H]` Everything that should rank must be in the first HTML response: title, description, canonical, h1,
  main copy, internal links, JSON-LD. Test with a plain fetch without JavaScript, then compare with the
  rendered DOM (title, h1, canonical, link count, JSON-LD count, word count).
- `[H]` Time-sensitive structured data (price, availability) belongs in server HTML `[U]` for Shopping
  crawls; the principle (server HTML is the safe source of truth) is a default.
- `[H]` Pitfalls: client-side-only head tags; hydration errors blanking the page; service worker returning
  200 for any path; consent wall covering content in the first response; locale redirects by IP.
- Framework notes `[H]`, not re-fetched: Next.js (server components, `generateMetadata`, `notFound()` for a
  real 404, `app/sitemap.ts`), Nuxt (`useSeoMeta`, `routeRules`), Astro (static by default, `site` for
  sitemap), SvelteKit (`prerender`, `error(404)`). Read the framework's current docs before quoting code.

## Mobile-first indexing

- `[G:mobile-first]` (updated 2025-12-10) Mobile content is what is indexed. Equal primary content, title,
  description, structured data (Breadcrumb, Product, VideoObject first), and robots meta tags on both
  versions. Do not hide resources from Googlebot through robots.txt that differs between versions. Content
  that needs swipe, click or typing is not loaded. Use stable image URLs. Responsive design is easiest to
  maintain.
- `[H]` Test: fetch with a smartphone user agent and viewport, then desktop, and compare text, links,
  structured data and meta.

## Core Web Vitals

- `[G:vitals]` LCP up to 2.5 s, INP up to 200 ms, CLS up to 0.1, judged at the 75th percentile, mobile and
  desktop segmented, all three required. INP became stable in 2024 and replaced the previous interactivity
  metric. Field measurement is essential.
- `[H]` Poor boundaries: LCP above 4 s, INP above 500 ms, CLS above 0.25 (web.dev bands; not re-fetched
  this pass, check the page before quoting a "poor" label).
- `[G:page-exp]` Core ranking systems reward good page experience, but good report scores do not
  guarantee top rankings and relevance still wins.
- `[H]` Field first: CrUX or the site's own measurement decides; lab runs only explain. Pass or fail per
  template and per URL group, not per homepage. Request `seocli:check_performance` (E6.5).
- `[G:lcp]` Subparts TTFB ~40%, load delay <10%, load duration ~40%, render delay <10%. Steps: make the
  resource discoverable in initial HTML and use `fetchpriority="high"`; remove render-blocking CSS and
  sync scripts; compress, modern formats, CDN, cache control; cut redirects and use edge caching. Target
  2.5 s for 75% of visits. Never lazy-load the LCP image.
- `[G:inp]` Input delay, processing duration, presentation delay. Begin with field data; cut main-thread
  blocking at load; split event callbacks with `setTimeout`; reduce DOM size; avoid forced layout.
- `[G:cls]` Image `width` and `height` or `aspect-ratio`; reserve space with `min-height`; `font-display:
  optional` and fallback fonts; avoid animating `top`, `left`; use `translate`; keep pages bfcache-eligible.
- `[H]` Common causes on small-business sites: third-party tags and chat widgets (INP), consent banners and
  late fonts (CLS), unoptimised hero image (LCP), page-builder DOM size (INP).
- `[H]` Image budgets as defaults: content images under 200 KB, hero under 300 KB; modern formats with
  `srcset`; lazy-load only below the fold.
